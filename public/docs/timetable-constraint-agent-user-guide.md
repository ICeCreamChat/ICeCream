## Excel 模板

下载模板：`/templates/timetable-constraints-template.csv`

这个 CSV 可以直接用 Excel 打开，也可以另存为 `.xlsx` 后上传到智能约束助手。每行写一条约束，保留“原文描述”列最重要。

| 字段 | 填法 |
|---|---|
| 原文描述 | 用自然语言写完整要求，例如“王老师周三第3节没空”。 |
| 对象类型 | 填教师、班级、课程、教室、全校或教研组。 |
| 对象名称 | 填项目里已有名称；不确定时留空，系统会进入复核。 |
| 时间 | 填周几、第几节、上午、下午、单双周等。 |
| 强度 | 填硬约束或软约束；拿不准时建议写软约束。 |
| 备注 | 写原因、人工说明或需要教务确认的背景。 |

## FAQ

**问：系统会直接改我的课表吗？**  
不会。对话排课会先生成需求卡，确认后才应用；硬约束删除或放宽还需要二次确认。

**问：为什么有些需求需要补充？**  
缺少对象、时间、数量上限或存在多个同名对象时，系统会先追问。连续 3 轮仍不确定的内容会转到人工复核台。

**问：硬约束和软约束有什么区别？**  
硬约束是必须遵守的条件，例如教师不可排、班级占用、固定课节；软约束是尽量满足的偏好，例如主科上午、少空堂、课程分散。

**问：无解了怎么办？**  
先看约束满足度报告和冲突诊断。通常优先放宽软偏好、缩小不可排时间范围，或把个别硬约束改为人工确认后处理。

**问：AI 没联网或 API 不可用怎么办？**  
常见约束会自动降级到本地识别，无法确定的内容会进入人工复核。

**问：大项目求解要等多久？**  
30 个班以上会显示预计耗时和当前 Timefold timeout。默认上限为 300 秒，显式配置 `TIMETABLE_SOLVER_TIMEOUT` 时以配置为准。

## 试点流程

1. 选 2-3 套脱敏学校数据，导入教师、班级、课程、教室和任课计划。
2. 由教务角色按真实习惯输入约束，保留原始说法和确认后的结构化结果。
3. 运行排课，检查硬冲突、未排课、约束满足度报告和导出文件。
4. 把授权后的失败输入脱敏加入语料库，每两周复盘一次新增意图和模板。
5. 固化常用模板，例如小学早读午休模板、初中主科上午模板、跨校区教师模板。
